# QUALITY_CHECKLIST.md — чек-лист готовности «МОТОР»

Назначение: превратить расплывчатую цель «довести до идеального состояния»
в конкретный, проверяемый список. Claude Code должен сначала провести аудит
по этому файлу (отметить `[x]` / `[~]` частично / `[ ]` не сделано с кратким
комментарием), показать приоритизированный список несоответствий — и только
потом чинить, по одному пункту за раз.

Статус: `[ ]` не проверено · `[~]` частично · `[x]` подтверждено рабочим

## 1. Функциональная полнота

- [ ] Все ссылки/кнопки в UI каждого `apps/*` ведут на существующие роуты
      (нет 404 при клике из интерфейса)
- [ ] Регистрация и логин работают для всех ролей (owner, staff, client) во
      всех соответствующих `apps/*`
- [ ] Полный флоу «клиент → запись → диагностика AI → смета → оплата →
      закрытие заказ-наряда» проходит без ручных вмешательств в БД
- [ ] AI-агенты (Приёмщик/Диагност/Оценщик/Снабженец/Планировщик/Бухгалтер)
      обрабатывают edge-cases: пустой ввод, таймаут провайдера, невалидный
      JSON-ответ модели — без падения бэкенда
- [ ] Fallback-цепочка AI-провайдеров (Groq → Ollama → OpenRouter) реально
      переключается при отказе, а не только в теории
- [ ] Складской модуль: резервирование деталей и авто-заказ у поставщиков
      (Exist.ru/Autodoc) отрабатывают на реальных/тестовых кредах
- [ ] Финансовый модуль: P&L сходится с суммой заказ-нарядов за период
- [ ] Мультитенантность: данные одного тенанта не протекают в другой
      (проверить явно — фильтрация по tenantId в каждом query)
- [ ] ЭДО/отчётность (Диадок, Контур.Экстерн, Атол 54-ФЗ) — хотя бы happy path
      протестирован на тестовых кредах провайдеров

## 2. Дизайн / UX

- [ ] Единая система отступов, цветов, типографики согласована между всеми
      `apps/*` (нет визуального разнобоя между saas/admin/staff-web/client-web)
- [ ] Мобильная адаптивность всех веб-страниц проверена на ширине 375px
- [ ] У каждого экрана есть состояния: loading / error / empty (не только

- [ ] Формы дают понятную обратную связь при ошибке валидации (не просто
      красная рамка без текста)
- [ ] Тёмная/светлая тема (заявлена в ROADMAP, итерация 20) реально
      переключается и не ломает контраст текста

## Как использовать этот файл

1. Проси Claude Code пройтись по разделам **по одному** за сессию — не по
   всем сразу. Аудит одного раздела занимает разумное время и даёт
   проверяемый результат.
2. После аудита раздела — приоритизированный список правок, потом только
   работа по списку.
3. Обновляй статусы `[ ]`/`[~]`/`[x]` прямо в этом файле по ходу работы —
   это единственный источник правды о реальном состоянии проекта, а не
   HANDOFF.md/ROADMAP.md, которые описывают историю, а не текущее состояние.
