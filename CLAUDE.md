# CLAUDE.md — контекст проекта «МОТОР»

Этот файл читает Claude Code при старте любой сессии в этом репозитории.
Держи его в актуальном состоянии — это твоя главная защита от того, что
агент забудет контекст между сессиями.

## Что это за проект

SaaS-платформа для управления автосервисом (запись, заказ-наряды, склад,
финансы, AI-диагностика, мультитенантность). Коммерческий продукт,
тарифы 25к–55к ₽/мес + Enterprise. Прод: motor-app.ru, хостинг — Beget VPS.

## Структура репозитория

```
motor-app/
├── backend/          # Node.js + Express + TypeScript + Prisma API (монолит)
│   ├── src/agents/    # AI-агенты (Приёмщик, Диагност, Оценщик, Снабженец, Планировщик, Бухгалтер)
│   ├── src/routes/    # REST-эндпоинты
│   ├── src/services/  # Бизнес-логика, интеграции (1С, Диадок, Атол, Exist/Autodoc)
│   └── prisma/        # Схема БД, миграции
├── apps/             # Фронтенды, каждый — отдельное Vite/React приложение
│   ├── saas/          # Публичный сайт + регистрация (motor-app.ru)
│   ├── admin/          # Панель супер-админа платформы
│   ├── staff-web/      # Веб-кабинет автосервиса (владелец/мастер/приёмщик)
│   ├── client-web/     # Веб-кабинет клиента автосервиса
│   ├── staff-mobile/   # React Native / Expo — мастер
│   └── client-mobile/  # React Native / Expo — клиент
├── mobile/           # (legacy, проверить — не задвоено ли с apps/*-mobile)
├── packages/shared/  # Общий код между фронтендами
└── HANDOFF.md / ROADMAP.md  # история итераций — не всегда актуальны, сверяйся с git log
```

⚠️ **HANDOFF.md и ROADMAP.md устарели** — описывают более раннюю структуру
(`backend/ + web/ + mobile/`), тогда как сейчас 4 отдельных веб-приложения
в `apps/`. Не доверяй им слепо, ориентируйся на реальную файловую структуру
и `git log`.

## Grill-me перед реализацией

Перед реализацией новой фичи/проекта — сначала `/grill-me` (или
`/grill-with-docs`, если решения стоит сразу фиксировать в доках): вопросы
раундами по фронту решаемых развилок, с рекомендованным ответом на каждый.
К коду не переходить без подтверждённого общего понимания.

Если скилл не установлен: `claude plugins install mattpocock-skills`.

## Команды

```bash
# backend
cd backend && npm install && npx prisma migrate deploy && npm run dev

# любой фронтенд из apps/*
cd apps/<name> && npm install && npm run dev

# docker (полный локальный стек)
make up
make db-migrate
make db-seed
```

## Как работать над задачей «довести до идеального состояния»

Не пытайся охватить всё за один проход. Порядок:

1. Прочитай `QUALITY_CHECKLIST.md` и проведи аудит — отметь текущее
   состояние по каждому пункту, ничего не чини на этом шаге.
2. Покажи приоритизированный список несоответствий (сначала сломанный
   функционал, потом несостыковки UX/дизайна, потом полировка и тесты).
3. Работай по одному пункту за раз. После каждого изменения — прогоняй
   typecheck/lint/build (тесты — как появятся).
4. Периодически перечитывай этот файл и `QUALITY_CHECKLIST.md` заново —
   на длинной дистанции легко потерять фокус или начать чинить то, что уже
   починено.
